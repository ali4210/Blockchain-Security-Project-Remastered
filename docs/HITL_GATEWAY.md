# Human-In-The-Loop (HITL) Gateway Protocol

## Overview & Boundary Invariants
Executive HTML status reports generated by Zone 9 (`reports/*.html`, `reports/status.json`) are **strictly internal by default**.
- Local `.gitignore` excludes all `reports/` artifacts from git tracking.
- GitLab CI job `executive_status_report` archives reports solely as internal GitLab runner artifacts with a 7-day retention period.
- No autonomous agent (Agents A–G) has access to generate, export, or publish reports.

## External Sharing Authorization Procedure
External distribution or egress of executive status reports to third-party auditors, external repositories, or public portals is strictly prohibited unless authorized through the **Phase 9 HITL Release Gateway**:

1. **Human Operator Authentication**:
   - Only designated human security operators (`soc_operator` or `compliance_officer`) may authorize external publication.
   - Operator must generate an HMAC-SHA256 signed release token using `src/mitigation/quarantine_staging.py`:
     ```python
     from src.mitigation.quarantine_staging import SignedReleaseToken
     token = SignedReleaseToken(
         token_id="REL-REP-20261013-001",
         operator_principal="saleem_soc_lead",
         target_destination="external_audit_portal",
         commit_digest="<CURRENT_COMMIT_SHA>",
         expires_at="2026-10-14T00:00:00Z",
         signature="<HMAC_SHA256_SIGNATURE>"
     )
     ```
2. **Gatekeeper Validation**:
   - Execution of `./scripts/mirror-release-gate.sh <path-to-token.json>`.
   - The gate verifies signature validity, expiry window, author principal (strictly rejecting autonomous agent principals), and target destination before any external transmission.
